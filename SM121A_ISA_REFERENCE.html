1. Architecture Overview

SM121A is the architecture tag emitted by CUDA 13 for the GB10 chip (DGX Spark): Blackwell-generation SM in the same physical die as a Grace CPU (aarch64), backed by unified LPDDR5x memory (no HBM/GDDR device memory). The GPU and CPU share one 119 GiB physical pool; SASS-level memory semantics (LDG/STG/atomics over a 64-bit canonical address) are unchanged, but the performance physics differ from dGPU Blackwell (SM120) substantially (section 4).

nvcc 13.0 accepts -arch=sm_121a (family-specific variant of SM121; not listed by --list-gpu-code). nvdisasm -b SM121a (note lowercase 'a') disassembles raw binaries; cubin mode (-c) works as usual.

4.3d GPU-MMU translation path: no TLB-capacity cliff to 72 GiB; L2 not address-partitioned (iter33/34)

Dependent-load page chase (one 4-byte hop per page, random cycle over the whole footprint, __ldcg; probes work/q3/uwp5/memprobe5{,x}.cu; raw results/q3/uwp5_tlb{,_big,_xl}_raw.json; reports results/q3/UWP5_TLB_HUGEPAGE.md, UWP5X_TLB_CLIFF_FALSIFIED.md). Per-hop cost is flat ≈330–351 cy (≈136 ns = the pure DRAM floor) for every footprint 64 MiB–72 GiB and every host mapping mode (4K mmap + cudaHostRegister, 2M THP — confirmed fully collapsed 64 GiB AnonHugePages, cudaMalloc). The iter33 prediction of a translation cliff once the 4K-page working set exceeds the ~114 MB system LLC (≈55 GiB) is falsified up to 72 GiB (19M pages, ≈144 MB of PTEs): the reuse-free chase is already the cold-translation worst case, and its walk cost is not additive — upper page-table levels are shared by millions of pages and pin themselves in the LLC, so a GPU page walk costs effectively nothing beyond the DRAM touch itself. Practical consequence: host page granularity (4K vs 2M) is a non-issue for GPU-side access at any scale that fits RAM; do not tune THP for the GPU (CPU-side effects remain; Grace chase shows the textbook TLB cliffs and THP rescue on the same buffers). A Grace CPU control on the identical chain degrades 9→185 ns/hop (4K, 24 GiB) vs 108 ns/hop with THP — the asymmetry is real and GPU-favorable.

L2 partitioning (probe work/q3/uwp6/memprobe6.cu, raw results/q3/uwp6_l2partition_raw.json, report results/q3/UWP6_L2_PARTITION.md): restricting the chase set to lines with a fixed address bit (bits 17–23) never yields the hard 2×12 MiB signature (no clean half-capacity knee; fixed sets degrade slightly earlier than the 24 MiB control and converge with it by 32 MiB) — GB10 L2 behaves as a single shared 24 MiB cache with hashed slice/set selection. No partition-aware optimization surface exists for kernels.

4.3e Write paths & injection structure on unified memory (UWP7/8/12–17, iter42–120)

Bandwidth vs footprint curves (event-timed, read/write/copy separately, 64 KiB–4 GiB, report results/q3/UWP7_BW_CURVES.md, raw uwp7_raw.json): read peaks at 6.8 TB/s L1-resident (2–4 MiB aggregate), L2 plateau ≈2.0–2.2 TB/s (8–32 MiB), L2→DRAM knee 40–48 MiB (effective residency <100% of the 24 MiB), full DRAM plateau ≈128 MiB: read ≈240, write ≈197, copy ≈220 GB/s. Per-SM stores into L2 write ≈2× slower than reads (write-through L1, every store dirties a line).

Injection limits are structural, not occupancy. Stores: 32 B/cycle (≈81.4–81.9 GB/s) per TPC pair, shared — two blocks on the paired SMs {2k,2k+1} inject no more than one (UWP8, L2-slice regime, clock64-calibrated; re-confirmed at the 1 GiB DRAM plateau by UWP17 with zero dependence on 256/512/1024 threads/block and exact quantization 81.4 / 122.0 / 162.7 / plateau 199.5 at grids 1–2 / 3 / 4 / 6–8). The DRAM write plateau needs only ≈3 TPC pairs (6 SMs). Loads at DRAM footprint are per-warp: ≈1.16 GB/s per warp (388 ns × outstanding window), so the read plateau ≈240 GB/s wants 32 blocks×512 thr or 16 blocks×1024 thr. Third independent confirmation of the UWP9 TPC-pair map. Reports: UWP8_STORE_INJECTION_121a.md, UWP17_PARTIALWR_RMW_121a.md (raw uwp8{,b,c}_raw.json, uwp17{,b}_raw.json).

Mapping-mode law for a shared CPU↔GPU buffer (UWP12/13/45, 1 GiB, grid 192×512): cudaMalloc (carve-out) 242/196 rd/wr; cudaHostAlloc(Mapped|WriteCombined) 241/219 with full CPU access and verified two-way coherence — the fast shared-buffer choice on GB10 (CPU-side fill 24.6 GB/s, CPU-side read ≈27 GB/s 1-thread, not the originally reported 3.6 — uwp12f was a fresh-page-fault artifact, corrected in UWP13d/e); managed/hostRegister/pageable cap at ≈163/114. cudaMalloc regions SIGSEGV the host CPU (0% pagemap-present). Prefetch/advise hints are performance no-ops on this platform; cudaMemAdvise on host-mapped returns invalid argument. Grace↔GPU split of the 256-bit bus under contention: the budget partitions (≈200–232 GB/s combined), it never collapses (UWP3/4/11).

Default/Portable host-mapped read plateau (UWP13–15): above ≈0.5–1 GiB total footprint, hostAlloc(Default) reads sag 236→≈175 GB/s. Resolved mechanism: per-page translation cost on the cacheable sysmem path (TLB/GMMU; sparse 16 B-per-4 KiB-page probe collapses identically at ≈0-byte traffic), global-footprint-dependent (4×256 MiB == 1×1024 MiB), seq vs shuffled knees 384→512 / 256→384 MiB. Managed memory shares the identical translational path class (same 2.0×108 pages/s ceiling). No ISA or CUDA-API switch exists (advise no-op, st.global.cs/wt dead) — the only escapes are the WC class or carve-out. Parked, no probeable handle left.

Decomposition of the deflt-rd plateau scatter (UWP18, iter163): the historical ±170–205 GB/s spread is a mixture of (1) a stable per-allocation band ≈3–8 % (two 1 GiB deflt buffers measured alternately ×16 rounds hold a/b ≈ 191/177 GB/s throughout, clock-sampled) and (2) a global time drift ±5–6 % on second scale (one buffer swings 182–202 GB/s with no leverage from sleep/disturb-4GiB perturbations, SM-clock 2411–2528 MHz, or power 10–18 W). Footprint deepening saturates at ≈1 GiB (6 GiB filler on/off/on leaves a resident probe unchanged). Root cause parked (fabric power-state / GMMU-parameter candidates, no ISA/API handle). Report results/q3/UWP18_BIMODAL_PLATEAU_121a.md (raw uwp18{A,B,c,d,e}_raw.json).

Store-hint and partial-sector laws (UWP14/16/17): st.global.cs/.wt move nothing on any buffer class (≤0.3 % — no user-side L2-allocation switch). Interleaved read/write runs degrade only below 128 B run length on mapped-sysmem (4× penalty at 64 B), 64 B on carve-out. Partial-line stores: lines dirtied as whole 32 B sectors only keep the full carve rate (half-line = 197 GB/s); partially-dirtied sectors pay a read-for-ownership fetch each (all-4-sectors-partial → ≈144 GB/s regardless of 2–4× byte differences = sector-count cost; one-partial-sector lines are cheaper than full lines, 379 GB/s footprint). On WC buffers full 128 B-line merging is required for the top rate (half-line drops to 121); sparse 16 B-per-line stores run fastest on WC (458 vs 379 carve). Net rule: write whole sectors on carve, whole lines on WC.

Green-context partitioning (UWP15C): coscheduled quantum = 8 SM; default minSmPartition 8 yields only 4×8 groups on SMs 0–31 (a third of the chip unreachable); minCount ≥16 or the IGNORE_COSCHEDULING flag are required for full-chip green contexts (6×8 canonical slices, pair-id mod 6).

4.3f L1D band and the GCC “L1.5” level: fetch-side only, invisible to data (UWP19, iter166)

Pointer-chase in both load policies (random 128 B-line cycle, the exact UWP chain construction; 5 reps, median/IQR; best-of in the raw tables) closes the last unmeasured hierarchy bands. L1D hit = 43.2 cy (wave constant 43.19–43.24, IQR 0.000), full-hit plateau through 88 KiB, knee 88–96 KiB (96 KiB already 143 cy), transition band up to 128 KiB (≈263–269 cy), fully at the L2 level by ≈144 KiB (344.8 cy) — the effective data carveout of the 128 KiB L1TEX for a shared-free kernel is < 96 KiB. No intermediate data latency level exists: LDCA and LDCG agree to <0.03 % cycle-wise across 256 KiB–8 MiB (343.21–343.23 cy both). The L2 knee, refined ×1 after the coarse legacy ×4 sweep: flat 344.5–346.9 cy through 16 MiB (TLB-drift slope only), 18 MiB 385, 20 MiB 438, 24 MiB 717, LPDDR5x full-DRAM plateau ≈958 cy from ≈48 MiB — effective L2 ≈16–18 MiB for a random-128 B stream.

GCC attribution by counters (ncu 13.0, --clock-control none; the gcc__ namespace is new on GB10 and firmware-described as “requests sent to L1.5”): a 6.4 MiB ld.global chase stream produces gcc__cache_requests = 37 total (30 instruction-class hits + 1 constant + noise; data class ≈ 0) in both the L2 band and the DRAM band; a 192 KiB-code-footprint kernel produces 3,096 GCC requests, of which type_instruction hit/miss = 532/2,559, and GCC-miss spills to LTS. GCC is a per-GPC instruction/constant fill level sitting between L1i/L1c and LTS — the data path bypasses it entirely (typed lookup counters exist only for constant/instruction/tsheader). Hierarchy model for GB10 global loads: L1D (43 cy) → LTS (343 cy) → LPDDR5x (≈958 cy); instruction/constant fetches: L1i/L1c → GCC → LTS. Report results/q3/UWP19_L1_GCC_BAND_121a.md (raw uwp19{l1band,knees,ncu}_raw.txt).

4.2e UE4M3.4X lane model & fp4-without-scale numerics (iter10)

OMMA.SF.16864.F32.E2M1.E2M1.UE4M3.4X (scale_vec::4X), resolved by 287 single/joint-element probes (q3 OMMA_4X_LANEMAP; cubit encode re-gated EXACT vs fleet golden): unlike the E8 variant, all four A registers and both B registers are live; partner map (strict nibble diagonal): A r0×B r0 and A r2×B r1 feed c0/c1, A r1×B r0 and A r3×B r1 feed c2/c3; per-pair gain ×4, e2m1 decode textbook. Scale registers carry 4×UE4M3 bytes (decode = textbook OCP e4m3-signless: bias 7, subnormals 2-9·m/8, 0x7F = NaN). The per-lane effective scale is NOT per-4-element-subvector as the PTX spec suggests: each k-half (8 pairs) is scaled by the arithmetic mean of its two assigned bytes — sLo = (b0+b1)/2, sHi = (b2+b3)/2, proven on 5 asymmetric mixing points (e.g. h(2.0,0.5)=1.25) and uniform across all 8 pair positions. Single byte at 1.0 with the rest 0.0 therefore halves that half's contribution.

fp4 without block-scale computes raw-linear, not e2m1. QMMA.16832.F32.E2M1.E2M1 (kind::f8f6f4; proper fragment = 4 A regs + 2 B regs, same shape as the k64 OMMA forms): on silicon an isolated nibble pair in a low-nibble-only setting contributes araw·braw/16 (≡4·(araw/8)(braw/8) — the family ×4 gain with a degenerate uint4/8 element decode; the e2m1 sign bit counts positively). Confirmed on two independent paths: cubit-assembled harness and a real ptxas 13.0 kernel (identical instruction bytes, identical values 0.25 / 0.5 / 1.0 / 0.875). Same instruction with fp8 types (QMMA.E4M3.E4M3) is fully textbook (448·4 at 0x7E, NaN at 0xFF) — so the ×4 gain is intrinsic to the QMMA/OMMA family on this silicon and the fp4-in-f8f6f4 datapath fp4 byte semantics are fully mapped (results/q3/QMMA_E2M1_BYTEMODEL.md): the hardware consumes each byte as one micro-format element via a shared decode φ(x) = (−1)b5 · [b4=0: u4/16 | b4=1: 2b3·(1+m/8)], bits b7/b6 dead; a byte-position contributes 16·φ(A)·φ(B), terms additively over diagonal byte pairs. Verified EXACT on 1792+256 grid probes and 24/24 random dense vectors (both software paths identical). 4.2f OMMA.SF UR6 qualifier: scale-source is internal, not a UR pair; cold-state caveat (iter15)

4.2f₂ UR6 per-bit attribution & token semantics (iter164)

4.2g Warp-slot banding at ≥4 warps/SMSP is a code-placement artifact (iter24)

The m9 harness shows reproducible per-warp cycle bands at 4 warps/SMSP (e.g. 9.80/10.04/10.55/11.87 M cycles, one band per SMSP slot since warp→SMSP assignment is warp-index mod 4). Resolution (results/q3/M9Y_WARPBANDS_ALIGN.md): not a per-SMSP hardware asymmetry and not a clock effect (per-warp cycles/globaltimer = 2.5635 GHz everywhere; a lone CTA always lands on VIRTUALSMID 0). A code-identical loop merely shifted in placement (NOP padding, branch displacement unchanged) sweeps the band depth from 3.9% to 26.7% and the aggregate by up to ~20%; a clean placement (loop at 0x1e0) is flat on all 48 SMs simultaneously, while the banded placement (0x300) bands everywhere at once (per-SM median ~9%, max 23.9%, quantised phase states). Interpretation: i-fetch/dispatch phase-locking of a shared code image at ≥4 warps/SMSP. Practical rules: take physics from 8-warp medians (IQR ≤ 4.5%), record loop addresses in raw metadata, and treat ≤5% Extension (iter143, results/q3/M9Y2_DUALMMA_WARPBANDS.md): the banding needs a dispatch-bound stream sharing one code image at ≥4 warps/SMSP. Tensor-core-bound streams are immune by construction: single- and dual-role IMMA.16832 loops (canonical placements 0x300 and 0x400/0x2000, 64 IMMA/iter) run flat to 0.0–0.2% across all slots and all 48 SMs (16.02 cy/IMMA at 4 warps/SMSP = the m9w hard TC credit limit, so the TC pipe, not the dispatch phase, sets the schedule). A dual-role FFMA split (2+2 warps/SMSP per image, images 7 KB apart) falls below the sharing threshold and leaves only a two-state 2.0% residual — so MMA-heavy series (m9a_imma, m9w) carry no banding artifact even at 4 warps/SMSP.

4.2m. Register-file bank map of GB10: mod-2 banks, per-pipe read throughput (iter161)

M9-class SR_CLOCKLO probes (work/q3/m9rf2_iter161, raw results/q3/m9rf2_iter161_raw.json; canonical loop @0x300, grid=1, 16 warps = 4/SMSP, 20k iters × 7 reps, per-warp median) resolve the register-file structure left open by the iter154 2-source grid (which saw only a ~1% even-source bias and could not reproduce the LEPC-dependent effect). Three-source chains are decisive: the GB10 register file has two banks by register-number parity (Rn mod 2), with per-pipe read arbitration:

  • ALU pipe (IADD3, IMAD.WIDE): 2 reads/bank/instruction are free. Only all-three-same-parity forms stall: IADD3 R16,PT,PT,R16,R8,R10 (e,e,e) = 12.20 cy/op and the (o,o,o) mirror = 12.05, vs the imm anchor 8.24 (+3.9 cy/op); every 2+1 parity split measures 8.24–8.33 (free).
  • FMA pipe (FFMA): 1 read/bank/instruction. Each extra same-bank read costs +2.9 cy/op and stacks linearly: unique-reg splits (2+1) = 9.5 (+2.9 over the 6.72 two-read anchor), all-same-parity = 12.5 (+5.8), and the FFMA R16,R16,R8,RZ reuse form with both unique reads even = 9.52 (vs 6.72 for the odd-even mirror) — the operand collector dedups identical registers, then arbitrates by bank.
  • 64-bit even pairs straddle banks (lo→bank(n mod 2), consistent with the ERR-201/203 even-base law): IMAD.WIDE.U32 chained through R16:R17 with split-parity sources reads 4 regs 2+2 for free (16.32 vs 16.26 imm anchor); same-parity source pairs stack 3 reads on one bank and pay the same ALU-rate +3.9 (20.1–20.25), identically for pair base R18:R19.
  • The conflict cost is issue-throughput, not latency: a second interleaved independent chain changes nothing (eee+eee = 12.20, imm+imm = 8.24, FFMA eee+eee = 12.56), and a conflict+clean mix recovers only ~1.9 cy/pair — a replay in the operand collector, not a deeper stall.

Consequence for regalloc on sm_121a: avoid all-same-parity three-source forms (IADD3/FFMA) and same-parity source pairs beside wide accumulators; the constraint is new for the whole Blackwell-era stack (fleet never bank-mapped sm_120). Table unchanged (physics finding); closes the iter156 RF-bank-map park. Async-producer hazards (LEPC/S2R read-side, §4.2l) are a separate mechanism and remain parked for full scheduling calibration.

5a. PC-relative control-flow immediates (erratum 090, iter52)

Branch targets in SASS text are absolute addresses; the encoded immediate is PC-relative with a 16-byte (one instruction) bias. Two layouts exist, both verified bit-exact against the full q1 corpus (ptxas ground truth):

BRA / BRA.U / CALL.REL.NOINC / RET.REL.NODEC  (16,008 corpus instances + far anchors):
  imm21 = (target - addr - 16) >> 4            # signed, 21-bit, instruction scale
  imm[5:0]   @ word[23:18]
  imm[15:6]  @ word[43:34]
  imm[20:16] @ word[48:44]                       # 5 bits (iter52 fit had [47:44])
  sign       @ word[63:49] and word[81:64] = all-ones (imm<0) / all-zero (imm>=0)
  mode       @ word[33:32] = 0 plain / 1 BRA.U / 2 BRA.DIV / 3 BRA.CONV
  bits[17:16] = 0            range: ±16 MiB code window

BSSY[.RECONVERGENT] Bn, target                (6,268 instances):
  imm32 = target - addr - 16                   # signed, byte scale
  imm    @ word[63:32]

Note the decode/render consequence: nvdisasm renders RET.REL.NODEC R10, 0x0 (return to function entry) from any function offset — the immediate field holds −(offset+16)>>4, which needs bits beyond imm[15] at offsets past 0x7ff0 and bits beyond imm[19] only in functions larger than 8 MiB. The 21st bit (imm[20] @ word-bit 48) was confirmed at iter199 by a synthetic ptxas far-branch probe (erratum 206): the iter52 20-bit fit was exact on the whole q1 corpus only because every corpus kernel is ≪8 MiB (rq[19]==rq[20] there); it forged/lost word-bit 48 far branches. Tools fitted on short functions only (the fleet’s 16-bit model on the B300 corpus, or the older dword-split model) silently alias the truth in the small-offset regime.

5b. ISETP/UISETP .EX dual-predicate family (iter108; erratum 153)

The .EX (6-token) form writes two predicates and is the hardware multiword-compare chain primitive. ptxas never emits it (0 of 7,842 ISETP/UISETP corpus words on SM121A), but every anchor class decodes byte-exact in nvdisasm 13.0 and executes on GB10 silicon — a plain canon gap, which the pre-port table silently absorbed through 5-token keys (phantom -R9 operands, dropped .EX; fleet BUG-086 class).

Encoding geometry (bit-walk, anchor-verified): .EX discriminator = bit72; compare-op bits[78:76] (F,LT,EQ,LE,GT,NE,GE,T); bool-op bits[75:74] (AND=0, OR=1, XOR=2; 3 = .INVALID3); sign marker bit73 (default/U32) and bits{80,73} for .S64/.U64; Pd 3b@81, Pd2 3b@84, tok5 3b@87 + neg@90; carry-in 4b@68 (3-bit index + neg@71); bit91 = UR-side signature (UR/UISETP forms require 1, R/II forms 0; wrong flip decodes <ILLEGAL>). Legality grid: 5 keys × (8 cmp × 4 op × 4 sign) = 640/640 legal renders.

Silicon semantics (GB10, patch-cubin probes; AND shown, OR/XOR identical pattern): eqF = (Ra==Rb) raw equality, independent of the cmp-op; x = cmpRes for .T/.F, else x = eqF ? cin : cmpRes for relational compares; then Pd = x OP Pc and Pd2 = ~x OP Pc. On a==b the result is the carry-in — the classic U64 equality/multiword chain idiom. Bool-op 3 (.INVALID3) traps on execution (CUDA error 3/illegal instruction, 4/4 probes) despite a fully legal nvdisasm render — table rows therefore exist for decode fidelity only and the encoder refuses them fail-closed.

Port: +5 keys (ISETP_P_P_R_{R,II,UR}_P_P, UISETP_UP_UP_UR_{II,UR}_UP_UP) with 640 mod-groups. Gates: 480/480 EXACT (decode text + encode payload per group), 160/160 INVALID3 encoder refusals, full-corpus census 91,304 words zero-drift, ISETP/UISETP roundtrip 3,132/3,132 payload-exact. Open: a 6th candidate key (ISETP_P_P_R_UR_UR_P_P, the .EX twin of the native R_UR_UR form, erratum 119) awaits a field-base probe of its currently-empty parent.

Uniform path confirmed on silicon (iter110): the uniform twin UISETP.*.EX obeys the identical formula on GB10 — measured directly with UMOV-loaded UR operands, preset cin/c and BRA.U UPx control-flow readout of both dual outputs (38 launches, work/q2/uexprobe_iter110): Pd = x OP Pc, Pd2 = ~x OP Pc, x = eqF ? cin : cmpRes for relational compares, eqF poraw equality of the UR pair; 36/36 formula-EXACT across GE/OR/XOR/EQ-chain/NE-mux grids, and .INVALID3 traps on the uniform path too (2/2 rc=3 illegal-instruction).
